# NBDT — отчёт о доработке v0.4

Дата: 21 октября 2026 года. Основа: предоставленный ZIP исходников v0.3 и спецификация v1.1 (раздел 23). Ветка v0.4 не разворачивалась на живом сервере и не имела доступа к данным пользователя; существующее IndexedDB в его браузере не изменено.

## Что действительно изменено

| Направление | Изменение в коде | Отношение к требованиям |
|---|---|---|
| Guide navigation | Маршрут `/projects/.../systems/.../guide`, profile/device/stage в query, восстановление через History API | C03–C04 частично: навигация реализована, браузерная end-to-end проверка ещё нужна |
| Guide сохранение | `Accept & continue` ожидает успешной транзакции, при ошибке остаётся текущий этап | F02/C09 — исправлен преждевременный переход |
| Profile applicability | Добавлены iPadOS и macOS как platform; запрещено публиковать firmware/Domain Join/Registry/GPO checks в iOS/iPadOS/Android guide | F01/C05 валидация, потребуется проверка исходных реальных templates |
| Task schedule | Реальные ISO-недели вместо искусственного ограничения Week 28 для Weekly Tracker; до 520 недель от project.startDate | F06/C15: источник дат не менялся, синхронизация legacy Timeline отдельно |
| Report | H1, четыре существовавших KPI, явный режим редактирования Cyber вместо input в обычной таблице; ожидание записи | F05/F11/C19/C21: устройственный counts сохранён, но серверное право отсутствует |
| Registry | Фильтры Windows/iOS/iPadOS/Android/Linux/macOS и Wired/WiFi ищут соответствия среди опубликованных endpoint profiles | F10 — одна система остаётся одной карточкой |
| Import | Проверка уникальности identity с trim, наличия device/profile и единственности активного run на profile/device | C01/C20: усиленная проверка, тесты добавлены |
| Интерфейс | Общие navy/blue/status CSS tokens, ширина sidebar 240/72px, читаемые статусы и шрифты, учёт `prefers-reduced-motion` | F06/F09/C10–C14 — кодовые исправления; visual regression ожидает проверку реальным браузером |

| Data lifecycle | Сохранены существующие IndexedDB records и legacy report rows. Новые пустые проекты не копируют фиктивные системы из seed | C01/C22: миграция пользователей требует их резервной копии |

## Проверено сейчас

- **56 PASS / 0 FAIL:** узкие unit tests (`npm test`) для workflow-модели, URL, ISO-календаря, импорта, platform и многопрофильности.
- **0 TS/TSX синтаксических ошибок** (`npm run check:syntax` с доступным системным TypeScript).
- **Ограниченная проверка имён:** была выполнена после основных изменений, показала 0 unbound identifiers. Не эквивалентна `tsc --noEmit`.
- Нет свежего полноценного Chromium-прогона нового приложения: npm-пакеты не установлены.

## Что НЕ сделано (не выдавать за готовый корпоративный сайт)

1. Не реализованы SQL Server backend, API, организационная SSO/auth, роли на сервере и реальная совместная работа.
2. Не подтверждены `npm install`, `npm run build` и `npm run lint`: npm registry в среде сборки недоступен. Не формировать заявление «готовый production bundle».
3. Не выполнены новый Playwright end-to-end прогон всего App, визуальное сравнение исходных макетов на 1672×941 и полный WCAG-аудит. В ZIP оставлены v0.3 browser logs исключительно для исторического контекста.
4. Настоящие инвентарные данные, документация SharePoint и approval-процессы не поступили; реальные VLAN и IP не выдумывались.
5. Master Timeline/Cable Hub/Issue Tracker из v0.3 сохранены, но их функциональная регрессия в этой версии полностью не проведена.
6. Старые localStorage данные прежней версии требуют ручного backup/import; автоматического разрушительного reset или импорта нет.

## Пример сквозной проверки после установки npm

1. Overview → включить Local edit mode; Export project backup.
2. Systems → открыть существующую систему; скопировать URL и открыть в новой вкладке.
3. Добавить отдельный iPadOS endpoint profile, убедиться, что Windows BIOS/TPM/Domain Join нельзя опубликовать в нём.
4. Зарегистрировать **два настоящих тестовых asset IDs** в копии demo, опубликовать проверенный guide, стартовать отдельные runs.
5. Подтвердить Base → Ready → Deployment на устройстве A; проверить отсутствие прогресса у B.
6. Вернуться в Configuration Report; подтвердить 4 KPI и сохранение без прямого редактирования чисел.
7. В Weekly Tracker перейти к 2026-W53 и затем к 2027-W01; открыть Share URL после перезагрузки.
8. Проверить Browser Back/Forward, 320px, 390px, 768px, 1280px, 1672px и 1920px, повторить все сценарии с отключённым storage/в двух вкладках.

**Приёмка производственной версии ещё не пройдена.** Этот архив — доработанные исходники локального прототипа v0.4 с указанными ограничениями.
