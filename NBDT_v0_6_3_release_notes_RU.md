# NBDT v0.6.3 — Release Notes

## Основа

Исходник: `NBDT_Web_Project_v0_6_2_Weekly_Tracker_Reference.zip`. Версия v0.7 намеренно не использовалась. Другие экраны, legacy-данные и локальный IndexedDB сохранены.

## Реализовано

1. **Project-relative weeks:** Week 1 стартует точно `project.startDate`. Недели по семь суток, нумерация сквозная до Week 520. `28.03.2026` → Week 1 `28.03–03.04`, Week 2 `04.04–10.04`.
2. **Две вкладки:** Overview / List. Вкладка Week удалена. При открытии старого `view=week` отображается Overview.
3. **Нижняя навигация:** Project weeks, Week 1, Week 2…; стрелки и Today. Подсветка текущей недели по timezone проекта и выбранных недель. Новые URL используют `?week=12` для Week 12. Старые ISO deep links принимаются для совместимости.
4. **Правая панель:** компактные карточки задач со статусами Planned / Active / Done / Blocked; ручной Blocked запрашивает причину в той же панели. Owner и Helpers видят одинаковый глобальный статус. Дополнительный редактор открывается только по More.
5. **Inline Add assignment:** одна строка названия, автоподстановка Owner и выбранной недели, Planned по умолчанию. Сохраняется только после подтверждённой записи.
6. **Защита ошибок:** изменения сохраняются через существующий `handleAction`/IndexedDB; невозможен переход из Blocked в Done при открытом связанном Issue; ошибки показываются в панели, без ложного сообщения об успехе.
7. **Project start:** календарь сохраняет точную выбранную дату, а не ISO понедельник; при переносе начала проекта задачи не переиндексируются, а milestone dates сдвигаются на реальную разницу дней.

## Проверки

- 88 unit/static-тестов по внутреннему набору, включая быстрые изменения и не-ISO недели; точный результат см. в `verification/v0_6_3_tests.log`.
- Синтаксическая проверка TS/TSX и проверка незадекларированных идентификаторов.
- Парсинг CSS.
- ZIP integrity.

**Ограничение:** среда не располагает подтверждённым набором npm-зависимостей для полной Vite-сборки и нового визуального Chromium-регрессионного теста. Перед обновлением сайта запустить `npm install`, `npm run lint`, `npm run build` и проверить интерфейс в браузере. Данные корпоративного сервера отсутствуют: demo IndexedDB ≠ shared sync.

## Рекомендация по установке

Сделать Export project backup из старой версии. Развернуть новый код на том же Vercel-проекте для сохранения origin IndexedDB на том же браузере; не менять домен без переноса резервной копии. Проверить проектную дату начала в Edit mode. При необходимости импортировать ранее экспортированный JSON backup.
