# NBDT Hub v0.6.83 — исправление импорта OHC – Print Shop из Excel

## Исправлено

1. **Endpoint / Device Model:** при копировании Excel-шаблона с объединёнными ячейками в строке `Endpoint` могли появляться дополнительные пустые колонки (`Endpoint\t\t\t`). Старый обработчик пропускал такой заголовок, а модель на следующей строке могла ошибочно попасть в Description. Теперь заголовок сохраняется до следующего значения.
2. **Naming Convention:** точно такое же поведение исправлено для `Naming Convention`. Значение следующей строки, например `xxBATCHP01`, теперь импортируется как Naming и больше не попадает в список непонятных строк.
3. **Description:** короткое описание, расположенное после `Hardware deployment and configuration required` и перед `Endpoint`, сохраняется отдельно. Для приведённого примера: `Deployment venue`. Название модели не дублируется в описании.
4. **Разное форматирование Excel:** HTML-таблица и обычный текст из буфера больше не конкурируют как полностью независимые результаты. Импортёр совмещает дополняющие друг друга распознанные поля; если Excel объединил строку описания и модель, предусмотрена дополнительная корректировка.
5. **Без изменений в других функциях:** Device Type и выбранная иконка не перезаписываются при импорте модели. Applications, три Configuration Checklist, Lessons Learned и ручное редактирование работают как прежде. Неопознанные поля не должны очищать уже сохранённые значения.

## Проверочный пример OHC – Print Shop

| Поле | Корректное значение |
|---|---|
| System name | OHC – Print Shop |
| Description | Deployment venue |
| Device Type | PC (выбирается отдельно при создании системы) |
| Device Model / Endpoint | LENOVO - DESKTOP TC M75Q WIN11 |
| Naming Convention | xxBATCHP01 |

**После обновления** для уже импортированной карточки повторите **Import from Excel** и сначала посмотрите Preview: там должны быть отдельные `Description`, `Endpoint / Device model` и `Naming convention`. Нажмите Apply import, чтобы заменить ошибочно сохранённые данные.
