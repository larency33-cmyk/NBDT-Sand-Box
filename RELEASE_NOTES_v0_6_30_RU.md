# NBDT v0.6.30 — Configuration Report (approved reference)

## Что исправлено

В качестве основы использован утверждённый экран Configuration Report из переписки. В сравнении с v0.6.29:

1. Удалены обе нижние панели Legacy Report и Legacy aggregate editor — больше нет пустых белых прямоугольников под таблицей.
2. Удалены устаревший редактор агрегированных строк, 9 демонстрационных legacy-записей из исходников, старые обработчики их импорта и экспорта и поле `configReportRows` из текущей модели. При загрузке старого проекта это поле исключается из оперативных данных (в IndexedDB старое значение физически исчезнет при следующем сохранении проекта). Рабочие системы, реальные device runs, задачи, участники и вопросы не затрагиваются.
3. Название и подзаголовок теперь оформлены как в макете: Configuration Report / название проекта · Deployment overview. Предупреждение о режиме редактирования не занимает отдельную строку постоянно.
4. Четыре KPI имеют одинаковую высоту, спокойные белые поверхности, цветные иконки, крупные проценты и кольцевые диаграммы.
5. System readiness — единая белая панель с фильтром All / In progress / Not started и единой строкой: поиск, Venue, Assignee, Cyber, Columns.
6. Колонка Columns содержит и выбор отображаемых столбцов, и сортировку по системе/числу развернутых устройств.
7. Таблица получила ровную шапку, компактные строки, раздельные цвета прогресса Base/Ready/Deployed, компактный индикатор AW (с исходным значением в подсказке) и числовую постраничную навигацию, как в макете.
8. Верхний **Export data** выгружает XLSX только из действующих систем и реально зарегистрированных устройств.
9. **Import Report** больше не восстанавливает устаревшие агрегаты. После проверки файла и явного подтверждения импортирует только Owner/Cyber существующих систем. Показатели готовности могут изменяться **только** через реальные принятые device checklist runs.
10. Не изменялись левое меню, Weekly Tracker, Issue Tracker, System Registry или алгоритм принятия чек-листов.

## Важно о данных

Показатели макета (например 74 системы и 88% готовности) не внесены в приложение: это был дизайн-пример. В проекте с двумя системами без реальных устройств KPI продолжат отображать `—` до регистрации и принятия устройств. Это ожидаемо и предотвращает подмену статистики демонстрационными значениями.
