# NBDT v0.6 — приближение к пяти макетам

Дата: 21 октября 2026 года. Исходная база: **NBDT Web Project v0.5 Visual Redesign**. Это новая редакция исходного проекта, **не замена его статической картинкой и не изменение опубликованного сайта**.

## Что исправлено

1. **Weekly Tracker / Overview** — компактные строки сотрудников при отсутствии заданий, выразительная матрица с четырьмя колонками недель, более ясное выделение ячейки, индивидуальные цвета аватаров, отсутствие вложенной вертикальной прокрутки таблицы. Если выбранный четырёхнедельный период пуст, показывается ссылка на ближайшую неделю с настоящими назначениями из текущих данных. Даты и задачи не выдумываются.
2. **Weekly Tracker / Week** — исправлен заголовок `Week W04` → `Week 4`; автоматически открывается панель первого сотрудника, у которого есть задания в выбранной неделе, что приближает композицию к эталону с правой панелью. Её можно закрыть обычной кнопкой, повторное открытие — при смене недели/представления. Заголовки сотрудников и строки выровнены по таблице, убраны лишние второстепенные подписи в плотном десктопном режиме. Роль Owner/Helper и общий Task ID сохранены.
3. **System Registry** — сильнее выделены иконки и названия, стабилизированы отступы между описанием и техническими полями, обновлены карточки/кнопки/полоса метаданных. `Legacy steps` теперь отдельно подписаны, без выдачи их за опубликованные device completions. Отсутствующая документация остаётся недоступной кнопкой.
4. **System Guide** — приближены высоты и ширины ячеек Technical essentials, иконки, цвет подложки, Lessons Learned, три связанные стадии и область чек-листа. Старые шаги неопубликованного guide не объявляются завершёнными.
5. **Configuration Report** — изменён **реальный порядок JSX-блоков**: заголовок → KPI → заголовок System readiness и сегментный переключатель → фильтры → экспорт/колонки/сортировка → таблица. KPI крупнее, названия профилей вынесены во вторую строку таблицы, введены отдельные режимы All/In progress/Not started. Четыре процента KPI вычисляются только по реальным зарегистрированным устройствам; при отсутствии данных отображается отсутствие сведений, а не проценты из демонстрационного PNG.
6. **Общая оболочка** — единая палитра бренда, более точное оформление Sidebar и читаемые подписи `NBDT · PROJECT`, `Issues`, `Configuration Report` при сохранении селектора реального проекта.
7. **Адаптивность** — правила для узких экранов, компактного Guide, переносов фильтров отчёта и карточек систем, reduced-motion. Широкая матрица остаётся в отдельной горизонтально прокручиваемой области.

## Что намеренно не изменено

- Данные пользователя: люди, 89 исходных задач, 2 исходные системы, прежние legacy aggregates, технические параметры. Если данные содержат 2 системы, сайт не должен ложно показывать 72 из макета.
- Механизм IndexedDB, revision checks, импорт/экспорт, модели устройств, Guide publication, acceptance, Owner/Helper, роутинг и другие части исходного проекта.
- Не реализованы SQL Server, многопользовательская синхронизация, корпоративная авторизация, полноценный проверенный Vercel production-release — они не создаются одной CSS-правкой.

## Как проверить и опубликовать

1. Сохранить текущие реальные данные из интерфейса сайта в JSON Backup (перед изменениями в приложении).
2. Распаковать проект; иметь Node.js >=22.12.
3. Выполнить `npm install`, `npm test`, `npm run lint`, `npm run build` в среде с доступным npm registry.
4. Запустить `npm run dev`, открыть все пять страниц при 1672×941, 1440×900, 768×1024 и 390×844. Сравнить их с файлами `design_references/S1…S5`.
5. Для Vercel использовать Build Command `npm run build`, Output Directory `dist` (Vite). Нельзя объявлять успешную публикацию без прохождения проверок.

**Важно:** данные IndexedDB локальны для конкретного браузера/домена; загрузка одного и того же кода другим пользователем не синхронизирует данные. Новая версия не очищает IndexedDB и не выполняет скрытую миграцию.
