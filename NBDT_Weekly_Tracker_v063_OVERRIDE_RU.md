# Требования NBDT Weekly Tracker v0.6.3 — изменение исходной спецификации

Этот документ отражает новые решения заказчика и **заменяет** противоречащие ему требования об ISO-неделях, виде `Week` и создании задачи через отдельную форму из панели назначений в `NBDT_Website_Master_Specification_RU.md`.

## Календарная модель

* `project.startDate = YYYY-MM-DD` — точный первый день **Week 1**, без сдвига к понедельнику.
* Project Week N: `from = startDate + (N − 1) * 7 дней`; `to = from + 6 дней`.
* `task.startWeek` остаётся нулевым индексом, поэтому при отображении показывается `startWeek + 1`.
* Недели внизу: Week 1… Week 520; выделять выбранные четыре недели и текущую неделю. В конце года номер не сбрасывается.
* Текущая неделя определяется `floor((localToday(project.timezone) − project.startDate) / 7 days)`. Если текущая дата раньше начала проекта, Week 1 показывается без индикатора Today.
* По умолчанию открывается текущая проектная неделя как первая колонка. Параметр `?week=24` открывает Week 24; старые ISO bookmarks разбираются для совместимости, но новые URL их не создают.
* При смене даты старта порядок задач не меняется; даты milestones перемещаются на точное число дней между предыдущей и новой датой. Явные Due Dates остаются абсолютными.

## Интерфейс

* Оставить только `Overview` (4-недельная матрица) и `List` (задания выбранного 4-недельного диапазона). Вкладки Week нет.
* Нажатие на ячейку открывает одну правую панель выбранного человека и недели.
* Для каждого задания в панели показать название, роль Owner/Helper, select Planned / Active / Done / Blocked и небольшое действие More для расширенного редактора. Без вложенного отдельного окна для стандартной смены статуса.
* Изменение статуса производится по уникальному Task ID и моментально отражается у всех помощников после завершения записи. Нельзя обходить открытые связанные блокирующие Issue.
* Выбор Blocked без прежней ручной причины открывает поле причины прямо под задачей и кнопку Save blocker.
* `+ Add assignment` создаёт inline форму из одного поля `Task name`. После сохранения создать Task с выбранным Owner, startWeek, duration=1, статусом Planned. При ошибке не закрывать форму и не терять текст.
* Настройки профиль/система/checklist доступны в полном редакторе через More, но не являются обязательными для быстрого добавления.
* Не подменять реальные записи и milestones демонстрационными данными из изображений.

## Сохранение / доступ

* Быстрые действия только в локальном Edit mode; Viewer видит статусы в режиме чтения.
* Сохранение через существующий транзакционный `handleAction`, с ожиданием результата и отображением ошибки. Общая структура IndexedDB, резервных копий и имён Task сохранена.
