# NBDT v0.3: фактический статус

Это продолжение исходников v0.2, а не полностью завершённая реализация всей спецификации и не production-релиз. Живой сайт и корпоративные данные не изменялись.

## Что добавлено и подключено

- Новая форма задачи: Owner, Helpers, диапазон недель, Due date, система, связанные blockers, checklist и комментарии. Одна задача показывается у Owner и Helpers без создания копий.
- Отдельные endpoint profiles внутри системы: выбор, создание и редактирование технических параметров. Инвентарь, guide и device runs разделены по профилям. Вторичный профиль не наследует опубликованный guide или hardware основного профиля.
- Guide: последовательное принятие Base Configuration → Ready for Deployment → Deployment; переоткрытие ранней стадии сбрасывает последующие acceptance. Run привязан к snapshot версии guide.
- Результаты checklist: явные состояния, N/A с причиной, evidence reference и примечание. Публикация новой версии не меняет существующие runs; миграция требует причины и создаёт новый run.
- Configuration Report: выбор колонок, индикаторы Base/Ready/Deployed/Cyber, просмотр результатов устройств и фильтры. Количества устройств не подменяются legacy aggregate values.
- Overview: сводные показатели и переходы. Weekly Tracker: Owner/Helper, поиск, неделя, Board/List, Today, overdue и ISO week labels.
- Локальное IndexedDB-хранилище: транзакционная запись project record, revision check между вкладками, журнал изменений и явное состояние ошибки. При недоступности IndexedDB нет скрытого переключения на localStorage или сервер.
- Сохранение задачи, профиля и guide ожидает завершения записи; ошибка не закрывает форму. Добавлены предупреждения о несохранённых изменениях в новых редакторах и переходах основной навигации.
- JSON backup/import с предварительной проверкой и CSV exports. Импорт заменяет текущий проект после явного действия пользователя, а не выполняет автоматическое слияние.
- Мобильная кнопка навигации, адаптивные формы, страницы Guide и таблицы.

## Что ещё не завершено

1. Серверные API, SQL Server persistence, корпоративная аутентификация и серверная проверка ролей/стадий. Edit mode остаётся переключателем локального demo, не механизмом безопасности.
2. Многопользовательская синхронизация, серверный audit и разрешение конфликтов по отдельным полям. IndexedDB защищает только локальную запись между вкладками.
3. Полная регрессия исходных Master Timeline, Cable Hub, Issue Tracker, legacy editors и всех переходов. Они сохранены, но не включены в изолированные browser tests.
4. Полное соответствие каждого пункта спецификации, visual regression со всеми исходными скриншотами, полный keyboard/focus/accessibility audit.
5. Полная схема импорта, dry-run diff, корпоративные проверки внешних ссылок и attachment upload. Evidence здесь является текстовой ссылкой/идентификатором, а не загруженным файлом.
6. Автоматическая миграция прежнего localStorage не выполняется. Перед заменой старой версии нужно сохранить её данные; новая версия не удаляет старый localStorage.
7. Проверка Vite/Tailwind build и dependency-aware TypeScript lint в среде с доступными зависимостями. Рабочий lockfile ещё не пересоздан; package-lock.original.json оставлен только как справочная копия.
8. Публикация на Vercel или корпоративной инфраструктуре не выполнялась.

## Вывод

Архив содержит существенно доработанный и частично проверенный локальный demo. Называть его полностью завершённым сайтом или готовым production-приложением нельзя.
