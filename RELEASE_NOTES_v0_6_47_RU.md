# NBDT v0.6.47 — Guest / Admin / Super Admin (локальный POC)

Базовая версия: NBDT v0.6.46. Интерфейс страниц Weekly Tracker, System Registry, Issue Tracker, Configuration Report и Configuration Guide сохранён, новая система ролей заменяет переключатели `Edit mode`, `View mode`, `Edit systems`, `Done editing`.

## Роли и доступ

- **Guest** — вход не выполнен; доступен просмотр данных, поиск, фильтры, безопасный экспорт. Контекстные действия изменения данных (карандаши, добавление, удаление, принятие этапов) недоступны. В верхнем правом углу — `Guest · Read-only access` и кнопка `Sign in`.
- **Admin** — после входа доступны существующие карандаши и операции над записями Weekly Tracker, Systems, Guides, Issues и Configuration Report. Глобальный переключатель редактирования не нужен. Admin не видит страницу Administration и не может создавать пользователей или менять проекты.
- **Super Admin** — все возможности Admin, управление проектами и настройкой даты начала, плюс отдельная страница **Administration** в боковом меню. Создание Admin, отключение/включение, сброс пароля и изменение собственного пароля.

## Первый вход (только для тестового POC!)

- Username: `superadmin`
- Password: `NBDT-POC-2026!`

На первой загрузке создаётся корневой тестовый пользователь. Пароли хранятся в localStorage в виде PBKDF2-SHA256 хешей с индивидуальной солью. Сама начальная пара намеренно известна и доступна в опубликованном клиентском коде. **ЭТО НЕ КОРПОРАТИВНАЯ АВТОРИЗАЦИЯ.**

## Как проверить

1. В верхнем правом углу нажать **Sign in** и войти как `superadmin`.
2. В боковом меню выбрать **Administration** → **New admin**. Заполнить Full name, Username и пароль длиной минимум 12 символов.
3. Выполнить **Sign out** через меню в индикаторе роли, войти под созданным Admin.
4. Проверить карандаши и добавление записей на Weekly Tracker / Systems / Issues / Report, убедиться, что раздел Administration не доступен.
5. Войти снова под Super Admin: **Disable** временно блокирует аккаунт; **Reset** устанавливает новый пароль и аннулирует прежний локальный сеанс.

## Ограничения безопасности и хранилища

- Все учётные записи находятся **только в localStorage конкретного браузера/профиля**, а сеансы — в sessionStorage. Данные самих проектов продолжают храниться в IndexedDB.
- Учётные записи не синхронизируются между компьютерами. На каждом другом браузере создаётся свой отдельный тестовый `superadmin`. Очистка данных сайта удалит созданные аккаунты. Для тестирования смены роли выходите и входите в **том же браузере**.
- Пароли хешируются для гигиены данных, **но не обеспечивают реальную защиту**, так как контроль доступа полностью в браузере. Пользователь с инструментами разработчика может обойти проверки.
- **НЕ ИСПОЛЬЗОВАТЬ** для реальной корпоративной среды или с конфиденциальными данными. Перед выпуском требуется Node.js API, централизованное хранилище пользователей, серверная проверка прав (RBAC), защищённые cookies/session, журнал действий; желательно подключение корпоративного SSO. Нельзя просто переключать существующий `LOCAL_UI_MODE` на сетевой режим и считать локальную авторизацию безопасной.
- Пароль `superadmin` рекомендуется поменять после первого теста, но смена его в локальном POC не делает систему пригодной для production.
