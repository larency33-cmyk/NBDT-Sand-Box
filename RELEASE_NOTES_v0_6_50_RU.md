# NBDT v0.6.50 — окончательное выравнивание Issue Tracker

**Основа:** v0.6.49. Изменение касается только горизонтального позиционирования верхнего заголовка Issue Tracker.

## Причина проблемы

На широких экранах и при уменьшенном масштабе браузера CSS приложения центрировал строку поиска, сводку и колонки Issue Tracker в контейнере с ограничением `--content-max: 1920px`. Однако заголовок `Issue Tracker` находился в отдельном HTML-элементе `<header>` без того же ограничения ширины. Поэтому при переключении страниц он визуально уходил влево. Предыдущие исправления выравнивали отступы, но не устраняли разницу в размере контейнера.

## Исправление

- Для `.nb34-issues > .nb34-hero` установлен тот же контракт, что и для остального содержимого: `width: 100%`, `max-width: var(--content-max)` и `margin-inline: auto`.
- Исправление внесено в отдельный финальный стилевой слой `nbdt-layout-v050.css`, подключённый после `nbdt-layout-v049.css`.
- Заголовок, поиск, сводка и колонки теперь выравниваются по одной линии даже на очень широких экранах и при изменении масштаба.
- Данные, роли Guest/Admin/Super Admin, Issue Tracker, остальные страницы, модальные окна и обработчики действий не изменялись.

## Проверки

- 291 из 291 автоматического теста пройдены (включая 3 новые проверки выравнивания).
- `node scripts/check-syntax.cjs`: синтаксических ошибок нет.
- В изолированной визуальной проверке Chromium проверено совпадение левой границы заголовка/поиска/сводки/колонок при ширине viewport **1649, 2048 и 2560 px**.
- До исправления в воспроизведённом тесте при ширине 2560 px заголовок начинался на x=247, а блок поиска — на x=436. После исправления оба начинаются на x=436.
- Полная production-сборка Vite не проводилась: npm-зависимости в тестовой среде отсутствуют. Проверь деплой Vercel после обновления репозитория.
