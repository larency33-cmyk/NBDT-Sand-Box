# NBDT v0.6.52 — Assignment: справочник владельцев систем

**База:** v0.6.51. Добавлена отдельная страница **Assignment** и связь владельцев по точным названиям систем со страницами NBDT. Existing Weekly Tracker tasks/statuses and device readiness history are retained.

## Assignment

- Новая страница в боковом меню, доступная Guest, Admin и Super Admin; маршрут `/projects/{projectId}/assignment`.
- Исходные данные взяты из предоставленной пользователем таблицы: **13 сотрудников, 108 назначений**, должности ITO / ITSS, точные даты присоединения и строки **Project 0–12**. Имя, должность и дата расположены строго над персональной колонкой; аватар — круг с первой буквой имени.
- Широкая таблица: фиксированные заголовки сотрудников и левая колонка проектов, горизонтальная и вертикальная прокрутка данных без видимых скролл-баров. Поиск по сотруднику/названию системы и фильтр должности.
- Для Admin / Super Admin: маленький карандаш редактирования в каждой занятой ячейке, добавление в пустую ячейку или через плюс в шапке сотрудника, удаление с подтверждением и **drag-and-drop** для переноса назначения к другому сотруднику. Слоты пересчитываются автоматически; при переполнении таблица увеличивает число строк. Guest не может менять назначения.
- Экспорт Assignment в CSV.

## Assignment — единый справочник Owner

- Хранится одним отдельным глобальным ресурсом `nbdt_assignment_roster_v052` в существующем IndexedDB demo-store; используется всеми проектными страницами внутри этого браузера. После сохранения интерфейс перестраивает владельцев автоматически.
- Совпадение: **строго полное название системы**, игнорируются только регистр и лишние пробелы. Частичные названия, исправления опечаток, синонимы, расширение аббревиатур и аналогии не рассматриваются. Например, `Crew Debit` не совпадёт с `CREW DEBIT KIOSK`.
- Для уникального совпадения Owner берётся из Assignment. Для названия, назначенного нескольким сотрудникам, отображаются **все совпавшие владельцы**, без произвольного выбора одного. Если совпадения нет, существующее значение Owner остаётся без изменений.
- System Registry: отображает Owner и предлагает фильтрацию владельцев из Assignment, CSV экспорт использует разрешённого Owner.
- Configuration Guide: Owner определяется через Assignment; ручное редактирование этого поля отключено для найденных совпадений.
- Configuration Report: колонка Owner, поиск, фильтры и экспорт берут данные из Assignment, если совпадение есть. Пользовательские старые Owner сохраняются как резервные для систем без совпадения.
- Weekly Tracker: если название задания или связанной системы совпадает, в подробностях задания и tooltip показывается System Owner из Assignment. Назначенный исполнитель задачи (`memberId`) не переписывается — это отдельная роль и исторические данные.
- Issue Tracker: System Owner доступен во всплывающей подсказке у названия системы; исполнитель issue остаётся отдельным от владельца системы.
- Справочные поля (Assignment owner) вычисляются при чтении, а не переписывают исходные данные задач, систем или устройств. Изменения сохраняются в единственном справочнике.

## Проверки

- **300/300 unit / structural tests** успешно пройдены, включая полную выборку сотрудника, дат и систем, строгие и неоднозначные совпадения, добавление, удаление, перетаскивание, динамические строки, маршрутизацию и автоматическое обновление отображаемого Owner.
- `npm run check:syntax`: 0 ошибок. Дополнительно проверены новые TSX/модули.
- Chromium: изолированная HTML-фикстура матрицы на 1650 × 920, проверено 14 колонок (плюс Project), 13 строк, горизонтальная прокрутка 2277 px внутри фиксированной области шириной 1396 px; наружного переполнения нет. Изолированная проверка не является полным end-to-end тестом React.
- **Ограничение проверки:** production build Vite и полный typecheck нельзя подтвердить в этой среде из-за недоступных npm-зависимостей (`@types/node`, `vite/client` и др.). После загрузки в GitHub проверь сборку Vercel и сохранение DnD в реальном браузере.

## POC, многопользовательский доступ и синхронизация

- Справочник и аккаунты сейчас **локальные для браузера**. Источник единый **внутри этого экземпляра NBDT**, но не общекорпоративный сервер. Для синхронизации на разных устройствах нужен корпоративный backend Node.js, единая база данных и серверная проверка прав.
- Для резервного копирования назначений на текущем этапе используй Export CSV на странице Assignment. Это отдельные данные, они **не входят в текущий проектный JSON-экспорт**.
- Старые значения Owner, история задач, стадии готовности и роли Guest/Admin/Super Admin не мигрировались принудительно.
