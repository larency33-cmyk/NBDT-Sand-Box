# NBDT v0.5 — переработка внешнего вида по пяти эталонным макетам

Дата: 21 октября 2026 года. Основа: **переданный исходный проект v0.4**, не новый лендинг. Цель — довести пять основных рабочих экранов до согласованной композиции S1–S5, **не подменяя рабочие данные демонстрационными** и не ломая локальный workflow.

## Что изменено

| Экран | Новая реализация | Источник сравнения |
|---|---|---|
| System Registry | Новая шапка, поиск + Platform/Connection/Owner, 3/2/1 колонки карточек, размер заголовков и полей, подвал с реальной пагинацией по 6, CSV экспорт всего отфильтрованного набора, Add system по правам, документация без фиктивных ссылок, System details как отдельное действие | `design_references/S3_system_registry.png` |
| Guide / Configuration checklist | Уплотнённая шапка, четыре визуальные колонки Technical essentials с настоящими outline-иконками, заметки Lessons Learned, последовательные направленные сегменты Base → Ready → Deployment, крупные checkbox, выделенный основной чек-лист, навигация по стадиям, read-only preview наследованных шагов для неопубликованного guide | `design_references/S5_POS_configuration_checklist.png` |
| Weekly Tracker — Week | Заголовок выбранной ISO-недели, группы с аватарами, структурированные Task/Role/Status/Due, сводка в панели человека Active/Planned/Done/Blocked, Create new task / Add assignment (через существующий Task Editor) | `design_references/S1_week_task_list.png` |

Дополнительно унифицированы базовые цветовые CSS-токены из спецификации v1.1 (navy sidebar / `#0066F5` brand / pale blue canvas), типографика, обводки, визуальная иерархия и breakpoints. Стили сведены в **один `redesign.css`**, а не в множество конкурирующих файлов. На малых экранах происходит перенос элементов, без `zoom`/глобального `scale`.

## Что намеренно НЕ изменено

- Действующие project names, task names, statuses, участники, сроки, systems, profiles, guides, устройства, legacy aggregates и IndexedDB: текущие две реальные локальные системы не превращены в 72 макетные записи.
- Статусы в хранилище `In Progress` / `Completed` **визуально** отображаются как Active / Done без изменения сериализованных значений.
- Guide без опубликованной версии **не разрешает отмечать/засчитывать** старые legacy-чек-листы. Пользователь может видеть их, но для реального device run нужен опубликованный guide + зарегистрированное устройство.
- Показатели Deployment не выдуманы: при отсутствии registered devices KPI остаются `—`, как в v0.4.
- Оригинальные Master Timeline, Issue Tracker, Cable Hub, редактирование задач и профилей, JSON backup/import и защита локальной записи сохранены.
- Ни SQL Server, ни серверная авторизация, ни корпоративный SharePoint не подключены. Нельзя считать local edit toggle системой прав.

## Проверки v0.5

- `npm test`: **64 PASS**, включая 56 существовавших тестов и 8 новых **статических контрактов оформления**. Статические контракты проверяют структуру и классы, но не заменяют отрисовку в браузере.
- `npm run check:syntax`: **0 синтаксических ошибок** в TSX и Vite config.
- `node scripts/check-bindings.cjs`: **0 unbound identifier errors** в ограниченном статическом анализе, при 15 внешних модулях без разрешения.
- CSS: `tinycss2` — **0 top-level parse errors**.
- **Полный `npm install` не удалось выполнить:** среда не получила пакеты из npm registry. Соответственно, `npm run build` сообщает `vite: not found`, `npm run lint` не находит typings Node/Vite. Это не доказанные дефекты исходников, но и **не подтверждение успешной сборки**.
- **Chromium visual regression v0.5 на настоящем App не выполнен**. Фактическое пиксельное сходство 1672×941 и другие viewport нужно проверить в среде с зависимостями. Прошлые скриншоты относятся к v0.4, а не к этому архиву.

## Запуск/проверка у себя (Windows)

1. Сначала в текущем сайте зайти в `Overview → Demo data, backup & audit` и **Export project backup**. IndexedDB привязана к origin; смена домена или браузера сама не переносит данные.
2. Распаковать в новую папку. Не удалять копию v0.4 и не перезаписывать единственный backup.
3. Запустить `START_WINDOWS.cmd` (Node.js 22.12+ и доступ к npm registry) либо выполнить `npm install`, `npm run check:syntax`, `npm test`, `npm run lint`, `npm run build`, `npm run dev`.
4. Просмотреть 5 экранов на 1672×941, 1440×900, 1280×800, 768×1024, 390×844 и 320×740 (zoom 100%). Сравнить с папкой `design_references/`, убедиться в отсутствии скрытых полей, неработающих кнопок, переполнений и потери данных.
5. Для Vercel использовать уже настроенный `vercel.json` (Vite, `dist`, SPA fallback); сначала проверить успешную сборку и резервную копию. **Текущий production/deployed URL этим архивом не изменён**.

## Известные границы

- Full Vite production build и pixel-level screenshot comparison не пройдены в данной среде из-за недоступных пакетов. Не называть проект протестированным production-релизом.
- Таблица матрицы desktop на узком viewport прокручивается локально; мобильный режим By person доступен отдельно.
- Новый visual design не решает исходные задачи серверного доступа, корпоративных интеграций и импорта legacy-records.
- Отдельные устаревшие legacy-экраны (Master Timeline, legacy aggregate editor, Issue Tracker) не прошли самостоятельную визуальную полировку на уровне пяти S1–S5.

Основная спецификация включена в архив: `NBDT_Website_Master_Specification_RU.md`.
