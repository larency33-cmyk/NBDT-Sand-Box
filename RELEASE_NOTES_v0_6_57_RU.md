# NBDT v0.6.57 — вставка колонок между сотрудниками (Assignment)

**Основа:** v0.6.56. Все функции v0.6.56 и исходные назначения сохранены.

## Изменения

- На странице **Assignment** захват **Move column** переносит **всю колонку** сотрудника со всеми отображаемыми системами. Вместо обмена местами двух людей колонка **вставляется в выбранную позицию**, а остальные сотрудники последовательно сдвигаются.
- **Левая половина** заголовка другого сотрудника — вставка **перед** ним; **правая половина** — **после** него. Вставка возможна в начало, середину и конец таблицы.
- Во время перетаскивания по всей высоте таблицы отображается тонкая ярко-синяя **линия вставки** по соответствующей границе; во всплывающей карточке появляется подсказка **Insert before/after**. Целевая колонка также подсвечивается.
- Перетаскивание за пределы заголовков, на себя или на позицию, где колонка уже находится, не меняет порядок.
- **Системы, уникальные ID сотрудников, должности, даты присоединения и Owner не меняются**: сохраняется только новый порядок колонок в `assignmentRoster.people`, включая CSV-экспорт и локальное хранилище IndexedDB.
- Перемещение отдельных систем между владельцами по-прежнему выполняется отдельным захватом внутри ячейки. Guest не получает возможность переставлять колонки.

## Тестирование

- **320/320 тестов прошли**, включая проверки вставки перед/после, первого/последнего столбца, отсутствия случайного обмена, сохранения 108 назначений, Guest/Admin и исполнения реального обработчика TSX в изолированном окружении.
- `npm run check:syntax`: успешно; `scripts/check-symbols.cjs`: успешно (проверка неопределённых имён / порядка инициализации).
- **Полный Vite production build и реальный браузерный smoke-test не выполнены в этой среде:** нет установленных пакетов `node_modules` (`vite: not found`). GitHub Actions release gate должен выполнить сборку и открытие всех маршрутов после загрузки.
- В проекте сохраняется обязательный release gate, предотвращающий повтор белого экрана после двух предыдущих ошибок. Успешные unit-тесты не являются подтверждением работы опубликованного сайта.

## Установка

Поставляются (1) полный архив проекта и (2) архив только новых и изменённых файлов относительно **v0.6.56** с точным сохранением расположения файлов в GitHub. Загружать второй архив в корень GitHub-репозитория с заменой одноимённых файлов; затем проверить GitHub Actions и Vercel build.
