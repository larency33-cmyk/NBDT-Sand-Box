# NBDT Hub v0.6.85 — System Registry: стабильные карточки и единый список Owner

## Что изменено

1. **Карточки System Registry** теперь занимают фиксированные колонки сетки. На широких экранах — три равные колонки, на более узких — две, на мобильных — одна. При фильтрации до одной или двух карточек пустые места остаются пустыми, а сами карточки не растягиваются на всю строку.
2. **All owners** формируется **только из списка сотрудников Assignment** текущего roster. Варианты `Legacy: ...` из старого `project.members` удалены.
3. Поиск систем по выбранному Owner проверяет **назначения систем в Assignment** по `personId`, включая совместные назначения нескольким сотрудникам. Старое системное поле `assigneeId` не подмешивается.
4. Фильтр Owner в System Registry теперь имеет собственное состояние. Фильтрация исполнителей в **Issue Tracker не затрагивается**.
5. Не менялись данные, сохраняемые в браузере: Assignment, владельцы систем, описания и Configuration Guides сохранены.

## Что проверить на сайте

1. **System Registry:** без фильтра видны три одинаковые по ширине карточки в ряду на широком экране.
2. Введите `crew de`: если осталась одна карточка, она занимает место первой колонки, а не всю ширину.
3. Раскройте **All owners:** есть сотрудники Assignment, но нет `Legacy`.
4. Выберите сотрудника с несколькими системами в Assignment: отображаются только его системы, включая shared. После **Clear filters** снова показываются все системы.
5. Перейдите в Issue Tracker и обратно: выбор Owner в System Registry не должен менять фильтр Issue Tracker.

## Примечание о тестировании

Добавлены Node-регрессионные тесты `tests/system-registry-v085.test.mjs` для CSS-макета, источника списка Owner и корректного сопоставления Assignment. Production Vite build и реальный браузерный smoke-test следует проверить в среде с установленными зависимостями.
