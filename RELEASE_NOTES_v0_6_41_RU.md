# NBDT v0.6.41 — Configuration Guide: inline editing + functional checklists

Основа: v0.6.40. Основной утверждённый дизайн страницы Guide и System Registry сохранён.

## 1. Configuration checklist
- Три стадии оформлены цельными CSS-chevron стрелками с выразительным кончиком и V-образным переходом. Удалён повёрнутый квадрат / «ромбик» предыдущего варианта.
- Для обычного просмотра гайда (без выбранного устройства) добавлен независимый `guideReview`: можно отмечать шаги, нажимать **Save checks**, принимать текущий этап через **Accept … and continue** и переходить к следующему.
- Второй и третий этапы становятся доступны для отметок только после принятия предыдущих этапов. Изменения уже принятой стадии требуют подтверждения и обнуляют принятие текущей и последующих стадий.
- При изменении перечня шагов проверки предыдущие подтверждения данного гайда инвалидируются. Шаги можно редактировать/добавлять/удалять только через карандаш секции; публикация новой версии Guide сохранена.
- Проверка гайда **не** считается подтверждением выполнения задач на зарегистрированном физическом устройстве: статистика развёртывания по-прежнему основана исключительно на `deviceRuns`.
- При открытии URL конкретного устройства используется существующая индивидуальная логика `runFor`, `setCheck` и `acceptStage`, с сохранением в его `deviceRuns`.

## 2. System Registry
- Карандаш на карточке открывает небольшой редактор только поля **Description** прямо в карточке.
- У кнопок Save / Cancel есть явная логика. Ошибка сохранения не закрывает редактор; описание можно вводить многострочно.
- Модель устройства, OS, Connection и Naming продолжают отображаться из `guideDraft` / `publishedGuide`, без параллельного редактора данных в Registry.

## 3. Configuration Guide — локальное редактирование
- У каждой секции отдельная кнопка-карандаш: Device, Network, Access & management, Applications, Lessons Learned, Configuration checklist.
- Вместо глобального тяжёлого редактора поля становятся редактируемыми внутри самой исходной секции, с локальными Save / Cancel.
- Параметры Device/Network/Access/Applications пишутся в тот же источник `Guide.technicalSnapshot`, что и прежде. Дополнительные поля Device и Access появляются только в режиме редактирования, не утяжеляя макет просмотра.
- Lessons Learned — массив записей с отдельным чекбоксом и длинным текстом, переносами строк и операциями добавления/удаления уроков.
- Исходные legacy-записи `lessonsLearned` остаются видимыми и могут быть преобразованы в новый массив при редактировании.

## 4. Совместимость / хранилище
- Данные и архитектура IndexedDB, существующие устройства и их история не удаляются.
- Данные `guideReview` и `lessonsLearnedItems` поддерживаются также в дополнительных endpoint profiles (`mergeProfile`).
- Изменения не затрагивают дизайн Weekly Tracker, Issue Tracker и Configuration Report.
